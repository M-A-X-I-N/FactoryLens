# FL-B160 — Implement Unreal dynamic-delegate root discovery

## State

`QUEUED`

Dependencies: `FL-B150`

## Description

Add supported root discovery for Unreal dynamic-delegate registrations such as `AddDynamic`, using a narrow registration-shape rule only to enumerate candidates and clangd semantics to prove the registered handler.

## Requirements

- Recognize the supported candidate shape represented historically by calls such as:

  ```cpp
  SomeDelegate.AddDynamic(this, &ThisClass::Handler);
  ```

- Treat textual/structural registration matching only as candidate enumeration; do not accept a handler until semantic target resolution proves the referenced method belongs to the analysis target.
- Resolve the member-function token semantically rather than trusting spelling alone.
- Emit normal FactoryLens root descriptors through the root-provider composition model.
- Preserve registration-site provenance, including source location and enough context to answer where the callback became registered.
- Aggregate repeated registrations into one handler root without discarding distinct registration sites.
- Preserve ordinary semantic symbol identity so discovered callback roots can feed the same outgoing-call/graph path as other roots.
- Reject unresolved or semantically mismatched registration candidates honestly.

## Historical B7 controls to preserve

The research proof chain used foreground semantic evidence equivalent to:

```text
registration candidate
  -> handler member token
  -> clangd definition / focused AST evidence
  -> target-project handler declaration/definition
  -> DYNAMIC_DELEGATE root + registration-site provenance
```

## Constraints / non-goals

- Do not build a generic arbitrary-C++ parser.
- Do not infer delegate targets from spelling alone when semantic resolution fails.
- Do not claim that discovering a registration proves the registration path executes in every runtime configuration.
- Do not claim that delegate registration alone proves when/how the delegate will broadcast.
- Do not fold SML native-hook, UHT/reflection, RPC/replication, or Blueprint dispatch into this task; those remain separate mechanisms.

## Acceptance criteria

Supported code discovers `AddDynamic`-style callback registrations and accepts handlers only after semantic target resolution, preserving every registration site's provenance while deduplicating repeated registrations by stable handler identity.

For the historical RSS2 control set, the supported implementation should recover all 13 known registration sites as the 11 known handler roots with zero unresolved candidates, unless current source has legitimately changed and that change is recorded explicitly.

## Validation

- Add deterministic controlled fixtures for positive registrations, repeated-handler aggregation, unresolved/mismatched candidates, and registration-site evidence.
- Exercise the supported provider against the current RSS2 workspace when practical.
- Compare any source drift against the historical B7 controls rather than silently weakening the gate.
