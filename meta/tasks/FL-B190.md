# FL-B190 — Validate the supported analyzer on RSS2 and Wiremod

## State

`QUEUED`

Dependencies: `FL-B150`, `FL-B160`, `FL-B170`, `FL-B180`

## Description

Prove the supported analyzer—not historical BX research scripts—works across the two required real Satisfactory mod specimens.

## Requirements

- Discover useful supported roots in RSS2 using the supported B150/B160 providers.
- Expand representative cross-file project-local paths in RSS2 through supported graph/call APIs.
- Discover useful supported roots in Wiremod/Circuitry.
- Expand representative cross-file project-local paths in Wiremod/Circuitry.
- Exercise the cohesive B170 headless integration path rather than manually choreographing individual research probes.
- Preserve root/edge provenance, stable identities, boundary classification, completeness, and diagnostics in the validation evidence.
- Record limitations/partial coverage honestly rather than hiding gaps.
- Use the current environment contract from `docs/ENVIRONMENT.md`.
- Keep analyzed Satisfactory/SML/Unreal source read-only.

## Known RSS2 controls / scar tissue

The supported B130 path already proved foreground local expansion of:

```text
URssBlueprintFunctionLibrary::IsSignDataSafe
```

and the historical B3 evidence proved the representative cross-file edge:

```text
URssBlueprintFunctionLibrary::IsSignDataSafe
  -> URssDownloadImage::IsStructurallySafeRemoteImageUrl
```

A cold supported B130 foreground query ran while `background_index=RUNNING` and did not yet expose that historical cross-file edge, even though same-file/project-local calls were available. B190 must therefore distinguish index readiness from semantic invalidity. If a cross-file acceptance specimen depends on background index state, wait/warm/retry explicitly or report the result as partial; do not silently replace the specimen with an easier same-file edge.

For RSS2 root coverage, reuse the B150/B160 configured controls where still present in current source rather than inventing a weaker validation set.

## Wiremod boundary

Historical B1/B2 research proved that the real compile metadata contains Wiremod/Circuitry translation units and that clangd can understand representative Wiremod-local symbols. Equivalent supported multi-level/rooted traversal was **not** completed during BX.

B190 is the task that must close that gap. Do not treat historical Wiremod semantic access alone as satisfying the supported-product gate.

## Constraints / non-goals

- Do not use migrated B1–B8 scripts as the implementation under test.
- Historical research may identify specimens/expected behavior, but the actual validation must flow through supported FactoryLens code.
- Do not require perfect incoming-call/reverse-index completeness.
- Do not promote known cold-index blind spots into false completeness claims.
- Do not expand this task into broad arbitrary-Unreal-project compatibility.

## Acceptance criteria

Current supported code—not BX scripts—successfully:

- discovers useful roots in RSS2;
- expands at least one representative cross-file RSS2 project-local path;
- discovers useful roots in Wiremod/Circuitry;
- expands at least one representative cross-file Wiremod/Circuitry project-local path;
- preserves concise evidence of provenance/completeness/limitations for both specimens.

## Validation

Run the supported B170 headless integration path against both real workspaces and preserve concise reproducible evidence.

For RSS2, include a cross-file specimen strong enough to demonstrate that index-backed traversal is genuinely available when required. For Wiremod, select and record a representative supported root/path rather than relying only on the old B2 symbol-resolution proof.
