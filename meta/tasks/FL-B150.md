# FL-B150 — Implement the root-provider interface and external-override provider

## State

`FROZEN`

## Description

Provide the supported root-provider seam and generic external-override discovery for framework/engine virtual overrides.

## Requirements

- Preserve the IDE-independent `RootProvider` abstraction.
- Discover target methods that semantically override authored declarations outside the target project.
- Use foreground Clang AST `OverrideAttr` / `FinalAttr` relations as the supported correctness path; reverse/background-index discovery may be an optimization later but must not be required for correctness.
- Preserve concrete external-base provenance/evidence.
- Accept authored dependency-mod, SML, FactoryGame, Unreal Engine, or other external source as generic external bases.
- Keep `TARGET`, `UNKNOWN`, and `GENERATED` / UHT relationships out of the generic external-override mechanism.
- Ensure discovered roots reuse the exact stable semantic symbol identities/descriptors used by supported outgoing-call expansion.
- Keep provider-specific class-qualified presentation identity in `RootDescriptor.label` when clangd's semantic symbol is only method-qualified/unqualified; do not mutate the semantic descriptor merely for display.

## Constraints / non-goals

- Generic external overrides are semantic facts, not automatically high-priority UI roots; emit them as `EXTERNAL_OVERRIDE` / `SECONDARY`.
- Do not conflate generated/reflection relationships with authored external overrides.
- Do not add unrelated framework-root families here.
- Do not make correctness depend on clangd's reverse `OverriddenBy` background-index relation, which B6 proved can have false negatives in this workspace.
