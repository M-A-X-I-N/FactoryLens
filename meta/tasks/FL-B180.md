# FL-B180 — Add automated analyzer tests and controlled semantic fixtures

## State

`QUEUED`

Dependencies: `FL-B150`, `FL-B160`

## Description

Complete and organize the deterministic automated test surface needed to validate the supported analyzer independently of expensive real-workspace checks.

This task is **not** starting from zero. B130/B140/B150 already established substantial deterministic coverage that must be preserved and extended rather than recreated.

## Existing baseline to build on

Already-landed coverage includes:

- core graph traversal/cache tests for deduplication, cycles, shared nodes, bounds, cache reuse, failure retry, and cache clearing;
- fake-clangd persistent backend/session coverage;
- fake-clangd call-hierarchy coverage;
- deterministic external-override provider coverage, including semantic positive/negative behavior, exact symbol-identity reuse, real-style unqualified clangd names, and generated-base rejection.

Real workspace scripts under `scripts/` remain separate environment-specific evidence and should not be collapsed into fast fixture tests.

## Requirements

- Preserve and organize existing core graph/evidence tests.
- Add controlled semantic fixtures for every supported initial root/call mechanism, including the B160 dynamic-delegate provider once implemented.
- Add root-provider composition/merging coverage once multiple providers coexist.
- Cover stable identity reuse across root discovery, call expansion, and graph traversal.
- Test degraded/partial/error behavior where the supported model exposes it.
- Test evidence/provenance retention and deduplication, not only happy-path symbol names.
- Keep real-workspace validation separate from small unit/fixture tests.
- Avoid coupling core-domain tests to raw Rider/LSP implementation details.

## Constraints / non-goals

- Do not rewrite already-effective B130/B140/B150 tests merely to centralize them.
- Do not make fast CI depend on installed Satisfactory/Unreal/SML workspaces.
- Do not treat fake-clangd fixtures as substitutes for the later FL-B190 real-workspace gate.

## Acceptance criteria

The supported analyzer foundation has fast deterministic coverage for graph/evidence behavior, semantic backend/session behavior, outgoing calls, external overrides, dynamic delegates, multi-provider root composition, and representative degraded/error cases; expensive real-workspace checks remain separate.

## Validation

Run the relevant deterministic suites on both supported CI analyzer platforms. Verify that the test surface remains independent of machine-local Satisfactory/Unreal installations and that real-workspace acceptance stays in task-specific/integration validation.
