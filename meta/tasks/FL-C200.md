# FL-C200 — Establish the minimal supported Rider entry surface

## State

`QUEUED`

Dependencies: `FL-B190`

## Description

Turn the already-existing Rider plugin/build skeleton into the first supported Rider-side FactoryLens entry surface on top of the validated analyzer foundation.

FL-A030 already established the Kotlin/JVM IntelliJ Platform layout and proved plugin packaging/verifier builds in CI. C200 must not recreate that scaffolding.

## Existing baseline to build on

Already complete before this task:

- the root Rider plugin module exists;
- the production Gradle/Kotlin layout is established;
- the plugin packages/verifies in CI for the pinned Rider baseline;
- semantic/compiler logic already lives outside Rider UI code.

C200 begins at **runtime/product integration**, not repository bootstrap.

## Requirements

- Rider loads the existing FactoryLens plugin in the chosen supported Rider baseline.
- The plugin recognizes/detects an opened supported Satisfactory project/workspace well enough to establish the FactoryLens entry surface.
- Reuse the supported workspace/analyzer boundaries rather than moving compiler semantics into Rider.
- Surface unsupported/missing configuration clearly rather than silently doing nothing.
- Keep the entry surface minimal; analyzer lifecycle ownership belongs to the following C210 task.

## Constraints / non-goals

- Do not recreate Gradle/plugin scaffolding already completed by FL-A030.
- No polished explorer UI is required yet.
- Full analyzer session lifecycle wiring is FL-C210.
- Do not make Rider the semantic source of truth.

## Acceptance criteria

The existing packaged FactoryLens plugin loads in the supported Rider baseline and recognizes an opened supported Satisfactory project/workspace, providing a minimal visible/supported entry point without yet requiring polished root/call UI or full analyzer lifecycle integration.

## Validation

- Build/package/verify the existing plugin as a regression check.
- Exercise actual plugin loading and supported-project recognition in the pinned Rider baseline.
- Verify an unsupported/misconfigured project produces a visible controlled outcome rather than silent failure.
